## First: confirm it's isolated

On the **Live** screen, see whether Twitch, YouTube or Kick are still **LIVE** while one shows as **RECONNECTING** or **ERROR**. If they all dropped together, skip to your local network or the input signal.

## Don't end the others

1. Pause only the bad destination.
2. Open **Platforms** and use **Test the server** on that card.
3. Check whether the key was changed in the platform's dashboard.
4. Compare the ingest URL with the current official documentation.
5. Check the platform's status page.
6. Resume the destination and watch its bitrate for a few minutes.

## How to read the result

| Result                        | Likely cause                   | Next step                         |
| ----------------------------- | ------------------------------ | --------------------------------- |
| Server doesn't respond        | route, DNS, firewall or outage | try the alternate official ingest |
| Connects and then drops       | key, codec or platform limit   | review credentials and preset     |
| Bitrate fluctuates only there | route to that ingest           | switch that destination's server  |
| All start dropping together   | saturated local upload         | lower the combined bitrate        |

<Callout label="Don't paste a key into a support ticket" tone="important">
  If the platform told you to reset your stream key, update it in Corneta's
  vault. Don't send the key in a screenshot, chat or diagnostic.
</Callout>

The operational step-by-step is in [one platform keeps reconnecting](/en/help/troubleshooting/platform-reconnecting).
