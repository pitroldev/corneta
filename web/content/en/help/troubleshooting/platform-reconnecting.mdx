## Isolate the destination

1. On the **Live** screen, confirm that the other platforms are **LIVE**.
2. Click **Pause** on the destination that keeps reconnecting.
3. Open **Platforms**.
4. On the affected card, click **Test the server**.
5. Check the key and the URL in the platform's official dashboard.
6. Review bitrate, codec, resolution and FPS in **Quality**.
7. Go back to **Live** and click **Resume**.

## Pick the branch

| Confirmation                         | Likely cause                   | Fix                                   |
| ------------------------------------ | ------------------------------ | ------------------------------------- |
| server test fails                    | route, DNS, firewall or ingest | use an alternative official address   |
| authenticates, then drops            | key or platform rule           | reset the key and review the preset   |
| bitrate is over the limit            | incompatible settings          | lower only that destination           |
| official dashboard shows an incident | platform unavailable           | keep it paused and wait               |
| all of them start dropping           | local upload                   | lower the total and test your network |

The connector tries to come back on its own, but repeated attempts don't fix an invalid credential. If you reset the key, change it in Corneta too.

## If that didn't fix it

Write down the platform, the time, the previous status, the message and whether the server test passed. Export the safe diagnostics file. Never send a stream key, token or URL that carries a credential.
