## The status map

| Status            | What's happening                                  | What to do                                                       |
| ----------------- | ------------------------------------------------- | ---------------------------------------------------------------- |
| **Waiting**       | Corneta hasn't received a signal yet              | check the address and start streaming in your streaming software |
| **Connecting**    | the output is opening a session with the platform | wait; if it doesn't change, test the key and server              |
| **LIVE**          | the platform is receiving media                   | keep an eye on bitrate and dropped frames                        |
| **Reconnecting**  | the output dropped and is trying to come back     | investigate only the affected destination                        |
| **Paused**        | you stopped that destination                      | use **Resume** when you want it back                             |
| **BE RIGHT BACK** | the protection screen replaced the signal         | check whether it was a manual pause or OBS dropping out          |
| **Error**         | the attempt stopped with a known cause            | open the message and use **Try again** after the fix             |

## Waiting doesn't mean OBS is disconnected from the WebSocket

The WebSocket lets Corneta set up and control OBS. The video signal arrives over local RTMP. The OBS button can show **Set up** while Corneta keeps waiting, because OBS hasn't started streaming yet.

## When to ask for help

Write down the exact status, the affected platform and the message shown. If there's an error ID or operation ID, copy it as text.

Never share your stream key, WebSocket password, token, local path or a screenshot with a credential. Use [export safe diagnostics](/en/help/reports-and-data/export-safe-diagnostic).
